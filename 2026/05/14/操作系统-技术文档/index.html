操作系统

进程、内存、I/O、文件系统与零拷贝

1. 操作系统整体视图

操作系统是应用程序和硬件之间的中间层，主要负责资源管理和抽象封装。

常见职责：

模块 作用
进程管理 创建、调度、切换、终止进程和线程
内存管理 虚拟内存、页表、缺页中断、内存隔离
文件系统 文件、目录、权限、硬链接、软链接
I/O 管理 缓冲、设备驱动、中断、DMA、I/O 多路复用
网络管理 Socket、协议栈、收发缓冲区
并发同步 锁、信号量、条件变量、死锁处理

从应用程序角度看，操作系统提供的是一组抽象：

  • 进程：运行中的程序实例。
  • 线程：CPU 调度的基本单位。
  • 虚拟内存：每个进程看到的独立地址空间。
  • 文件：对磁盘、设备、管道、Socket 等资源的统一抽象。
  • 系统调用：用户态进入内核态请求服务的接口。

2. 进程与线程

2.1 进程

进程是资源分配的基本单位。一个进程通常拥有独立的虚拟地址空间、文件描述符表、信号处理方式、当前工作目录等资源。

进程的典型组成：

组成 说明
代码段 程序指令
数据段 全局变量、静态变量
堆 动态分配内存
栈 函数调用、局部变量
文件描述符表 打开的文件、Socket、管道等
进程控制块 PCB 内核维护的进程状态信息

2.2 线程

线程是 CPU 调度的基本单位。同一个进程内的多个线程共享进程资源，例如地址空间、打开文件、全局变量，但每个线程拥有自己的栈、寄存器上下文和线程局部存储。

线程优点：

  • 创建和切换成本通常低于进程。
  • 线程间共享数据方便。
  • 适合并发处理 I/O 或多核并行计算。

线程风险：

  • 共享内存带来数据竞争。
  • 锁使用不当会产生死锁、活锁、饥饿。
  • 单个线程崩溃可能影响整个进程。

2.3 进程与线程对比

维度 进程 线程
基本定位 资源分配单位 CPU 调度单位
地址空间 默认相互隔离 同进程内共享
通信成本 较高，需要 IPC 较低，可共享内存
创建切换成本 较高 较低
故障影响 一个进程崩溃通常不影响其他进程 一个线程崩溃可能导致整个进程异常

3. 进程间通信

进程间通信 IPC 用于让不同进程交换数据、同步状态或协作完成任务。

3.1 管道

管道是单向字节流，常用于具有亲缘关系的进程之间通信，例如父子进程。

特点：

  • 半双工，普通管道通常只能单向传输。
  • 数据按字节流传输，没有消息边界。
  • 适合简单的数据流转。

3.2 命名管道

命名管道 FIFO 有文件系统路径，不要求通信双方一定具有父子关系。

特点：

  • 仍然是字节流。
  • 可以被无亲缘关系的进程打开。
  • 适合本机简单 IPC。

3.3 信号量

信号量主要用于控制多个进程或线程对共享资源的访问。

常见用途：

  • 限制并发访问数量。
  • 实现互斥。
  • 实现生产者消费者同步。

信号量不是用来传输大量数据的，它更适合做同步和资源计数。

3.4 消息队列

消息队列以消息为单位进行通信，保留消息边界。

特点：

  • 发送方和接收方通过内核维护的队列通信。
  • 相比管道，更适合结构化消息。
  • 可能存在消息大小和队列容量限制。

3.5 共享内存

共享内存允许多个进程映射同一块物理内存，是速度最快的 IPC 方式之一。

优点：

  • 减少内核和用户态之间的数据拷贝。
  • 适合大数据量、高频通信。

缺点：

  • 本身不提供同步机制。
  • 需要配合信号量、互斥锁、条件变量等保证并发安全。

3.6 Socket

Socket 可用于同机进程通信，也可用于跨机器网络通信。

常见类型：

  • TCP Socket：可靠、有序、面向连接。
  • UDP Socket：无连接、尽力而为、低开销。
  • Unix Domain Socket：同机 IPC，性能通常优于 TCP Socket。

Socket 是分布式系统和网络服务的基础抽象。

4. 进程调度

调度器决定哪个进程或线程获得 CPU 时间片。

4.1 常见调度算法

算法 思想 优点 缺点
先来先服务 FCFS 按到达顺序执行 简单 短任务可能被长任务阻塞
短作业优先 SJF 优先执行预计时间短的任务 平均等待时间低 长任务可能饥饿，执行时间难预测
优先级调度 优先级高的先执行 可体现业务重要性 低优先级任务可能饥饿
时间片轮转 RR 每个任务轮流获得时间片 公平，适合分时系统 时间片过短会增加切换开销
最短剩余时间优先 SRTF 剩余时间短的任务优先 响应快 需要预估剩余时间
多级反馈队列 MLFQ 根据行为动态调整队列 兼顾响应和吞吐 实现复杂

4.2 上下文切换

上下文切换是 CPU 从一个任务切换到另一个任务时保存和恢复执行上下文的过程。

需要保存和恢复的内容包括：

  • 寄存器。
  • 程序计数器。
  • 栈指针。
  • 虚拟内存相关上下文。
  • 调度统计信息。

上下文切换不是免费操作。线程过多、锁竞争严重、I/O 阻塞频繁都可能导致上下文切换开销升高。

5. 死锁

死锁是多个进程或线程相互等待对方持有的资源，导致都无法继续执行。

5.1 死锁四个必要条件

条件 含义 是否容易破坏
互斥 资源一次只能被一个线程或进程占有 通常无法消除
请求和保持 持有资源的同时继续请求其他资源 可以破坏
不可剥夺 已持有资源不能被强制抢占 可以设计超时释放
循环等待 多个任务形成环形等待链 可以通过资源排序破坏

5.2 避免死锁的方法

常见策略：

  • 一次性申请所有资源，破坏请求和保持条件。
  • 按固定顺序申请资源，破坏循环等待条件。
  • 加锁设置超时，获取失败时释放已持有资源。
  • 减小锁粒度和锁持有时间。
  • 避免在持锁期间执行阻塞 I/O、远程调用或复杂回调。

6. 僵尸进程与孤儿进程

6.1 僵尸进程

僵尸进程是已经退出，但父进程还没有回收其退出状态的进程。它在进程表中仍保留一条记录。

产生原因：

危害：

  • 僵尸进程不占用大量内存和 CPU。

7. 虚拟内存

虚拟内存是操作系统提供的一种内存管理技术。它让每个进程看到一个独立、连续、巨大的逻辑地址空间，而不直接暴露真实物理内存。

7.1 为什么需要虚拟内存

虚拟内存解决了三个核心问题：

  • 地址抽象：程序使用虚拟地址，不需要关心物理内存位置。
  • 内存隔离：每个进程有自己的页表，不能随意访问其他进程内存。
  • 容量扩展：通过换页机制，让程序可用地址空间大于实际物理内存。

7.2 地址转换

CPU 访问内存时使用虚拟地址，硬件 MMU 会借助页表把虚拟地址转换为物理地址。

简化流程：

为了加速地址转换，CPU 内部通常有 TLB。

TLB 可以理解为页表缓存。命中 TLB 时，不需要完整查询页表；未命中时才进行页表遍历。

7.3 页表

页表记录虚拟页到物理页框的映射关系。

页表项通常包含：

  • 物理页框号。
  • 是否存在于内存。
  • 读写执行权限。
  • 用户态/内核态访问权限。
  • 脏页标记。
  • 访问标记。

现代系统通常使用多级页表，以减少页表占用空间。

7.4 缺页中断

当进程访问的虚拟页不在物理内存中时，会触发缺页中断 Page Fault。

处理流程：

  1. CPU 发现页表项无效或页面不在内存。
  2. 触发异常，陷入内核。
  3. 操作系统判断访问是否合法。
  4. 如果合法，从磁盘、交换区或文件映射中加载页面。
  5. 更新页表。
  6. 恢复用户程序继续执行。

缺页不一定是错误。例如按需分页、内存映射文件、Copy-on-Write 都可能触发正常缺页。

8. 页面置换算法

当物理内存不足，需要把某些页面换出内存时，操作系统会使用页面置换算法选择淘汰页面。

8.1 最佳置换算法 OPT

最佳置换算法淘汰未来最长时间不会被使用的页面。

优点：

  • 理论上缺页率最低。

缺点：

  • 需要知道未来访问序列，现实中无法实现。
  • 通常用于理论比较基准。

8.2 先进先出 FIFO

FIFO 淘汰最早进入内存的页面。

优点：

  • 实现简单。

缺点：

  • 可能淘汰经常使用的老页面。
  • 可能出现 Belady 异常，即分配更多页框反而缺页更多。

8.3 LRU

LRU 淘汰最近最少使用的页面。

思想：

优点：

  • 比 FIFO 更贴近局部性原理。

缺点：

  • 精确实现成本较高。
  • 需要维护访问时间或链表顺序。

工程中常使用近似 LRU。

8.4 LFU

LFU 淘汰访问频率最低的页面。

优点：

  • 能保留高频页面。

缺点：

  • 历史热点可能长期占据内存。
  • 对突发访问和阶段性访问适应较差。
  • 需要衰减机制才更实用。

8.5 时钟置换算法

时钟算法 Clock 是一种近似 LRU 算法。

核心思想：

  • 每个页面有访问位。
  • 指针像钟表一样扫描页面。
  • 如果访问位为 1，清零并跳过。
  • 如果访问位为 0，选择淘汰。

优点：

  • 成本低。
  • 效果接近 LRU。
  • 常用于实际系统。

9.1 硬链接

硬链接可以理解为同一个 inode 的多个目录项。多个文件名指向同一份文件数据。

11. I/O 模型

11.1 阻塞 I/O

阻塞 I/O 中，调用线程发起读写后会一直等待，直到数据准备好并完成拷贝。

特点：

  • 编程简单。
  • 每个连接通常需要一个线程或进程。
  • 大量连接时线程成本较高。

11.2 非阻塞 I/O

非阻塞 I/O 中，系统调用如果无法立即完成，会直接返回错误码，例如 EAGAIN。

特点：

  • 线程不会被单个 I/O 阻塞。
  • 需要应用层不断轮询。
  • 单纯轮询会浪费 CPU。

11.3 I/O 多路复用

I/O 多路复用允许一个线程监听多个文件描述符，当某个 fd 就绪时再进行读写。

常见机制：

机制 特点
select 跨平台较好，fd 数量有限，每次需要传入 fd 集合
poll 没有固定 fd 上限，但仍需线性扫描
epoll Linux 高性能方案，适合大量连接

11.4 信号驱动 I/O

信号驱动 I/O 中，进程注册信号处理函数，内核在数据准备好时通过信号通知进程。

这种模型使用相对少，复杂度较高。

11.5 异步 I/O

异步 I/O 中，应用提交 I/O 请求后可以继续执行。内核完成数据准备和用户空间拷贝后，再通知应用。

16. 总结

操作系统知识可以围绕四条主线理解：

  1. 进程线程：谁在运行，如何调度，如何通信。
  2. 内存管理：虚拟地址如何映射到物理地址，缺页如何处理。
  3. 文件与 I/O：数据如何从磁盘到网络，如何减少拷贝和切换。
  4. 并发控制：共享资源如何同步，死锁如何避免和排查。

对后端工程来说，操作系统不是孤立理论。线程池、Socket、epoll、PageCache、sendfile、进程状态、文件描述符、上下文切换都会直接影响服务吞吐、延迟和稳定性。真正掌握这些概念，关键是能把“概念名词”对应到实际运行时现象和排查工具上。
